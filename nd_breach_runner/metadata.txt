about=Builds the breach hydrograph (ND REG_05.2026 Section 5.1.1: Froehlich 2008/1995, MacDonald, Von Thun & Gillette, TR-60 or your own), optionally routes a PMF inflow with and without the breach, runs LISFLOOD-FP on a local DEM and extends the domain until nothing downstream matters, and can re-run the flood with ANUGA. Writes depth, velocity, arrival and WSE GeoTIFFs plus baseline, incremental, vector and EAP-map products. Includes sensitivity, cascade, nested-grid and Monte Carlo tools, rainfall-to-PMF, life-safety and damage estimates, animation, a Word submittal report, HEC-RAS import/export, a verification suite, a self-test for this QGIS, LiDAR/NLCD data tools and a hand-off to the ND hazard classification. Runs offline. LISFLOOD-FP (patched build) and ANUGA (own conda environment) are installed separately; see README.md.

changelog=3.12.0 - With ND Dam Hazard 2.22.0 and ND Dam Breach Screening 0.20.0 (damsuite 1.8.0). The computer is kept awake while LISFLOOD-FP, ANUGA or the built-in engine runs (Windows SetThreadExecutionState, macOS caffeinate, Linux systemd-inhibit when it works), beside the solver so Cancel still stops it; when it cannot, the log says so once and the run goes on; ND_DAM_KEEP_AWAKE=0 switches it off; the self-test has a line for it. Near-dam refine (REFINE_NEAR) is off by default again: LISFLOOD-FP 8.1 writes no maximum velocity for FV1 and 3.8.0-3.11.x put 0 ft/s in the fine box; when the refine is on and FV1 wrote no velocity, the ACC velocities are kept and the report says so. HEC-RAS model export: the run's culverts, bridges and notches in the downstream 2D area become connections inside the 2D area (weir from the terrain along the road, a culvert group or an open gap; option STRUCTURES, on by default; not opened in HEC-RAS, see README_HECRAS.md); runs record their structures with the inverts they used (structures_used). See README.md.
    3.11.1 - With ND Dam Hazard 2.21.0 and ND Dam Breach Screening 0.19.0. Shared suite code only: Suite data finds DWR unknown structures and dugouts in the dwr/ folder (dwr/_other too). No model change.
    3.11.0: With ND Dam Hazard 2.19.0 and ND Dam Breach Screening 0.18.0. Set up ANUGA without conda: a one-time tool (Checks tab, Plugins menu, ndbreach:setupanuga, ndbreach_cli.py setup-anuga) downloads micromamba (SHA-256 checked) and installs ANUGA from conda-forge into a private environment in the plugin data folder; the Runner finds it on its own (about 360 MB download, 1.6 GB on disk; not on ARM Windows or Linux). Works without installing LISFLOOD-FP: a patched LISFLOOD-FP is bundled for Windows 64-bit and Linux 64-bit (bin/, with its source and the GPL-2 text), and a built-in flood engine (numpy, same local-inertial method, same input files) runs on any computer; choose it with the new provider setting "Use the built-in flood engine" or the word builtin as the LISFLOOD-FP path. Fixes from the Elm River Detention Dam 1 run (see RUNNER_FV1_INSTABILITY.md). The near-dam fine run is checked before it is merged: water in the domain more than 10% above what was injected plus what was already ponded, boundary inflow after the flood, or a depth over twice the dam height reject it, and the ACC results are kept everywhere (the fine run used to be merged unchecked: max depth 39,137 ft). The fine run closes the upstream and side edges of its box (an edge not listed in the .bci is a wall) so it cannot import water through a free edge in the reservoir basin, and its clock follows the flood travel time to the box end instead of the main run duration. The dam line is raised to the top of dam in the model DEM (RAISE_CREST, on by default; the CREST_LINE layer, else a ridge traced from the DEM; the source DEM is not changed) so breach water does not spill back into the empty reservoir. DURATION_HR 0 = automatic as its help says, and the clock is lengthened while the flood is still moving. The resume key no longer includes the refine settings, so changing REFINE_NEAR reuses finished runs. The run report gains the late boundary inflow, the water in the domain against the injected volume, and the rejected-fine-run section. See README.md.
    3.10.0: Build a HEC-RAS 2D dam-breach model from a finished run (ndbreach:hecrasmodel; reservoir storage area, dam connection with the breach, 2D area from the flooded extent plus side and end buffers, normal depth boundary; all text files, projection and terrain GeoTIFF). A DEM without a unit in a State Plane feet CRS is no longer read as feet when its elevations only fit as metres. Flooded road lengths in the consequences tool are ground metres whatever the raster CRS. The LISFLOOD-FP executable and ANUGA Python parameters accept a file name without an extension (Linux, macOS). See README.md.
