changelog=0.20.0: With ND Dam Hazard 2.22.0 and ND Dam Breach Runner 3.12.0 (damsuite 1.8.0). Tool 7 keeps the computer awake while the flood model runs (beside the model; when it cannot, the log says so once and the run goes on; ND_DAM_KEEP_AWAKE=0 switches it off). Tool 7 enlarges the clip before the flood run when the downstream trace reaches its edge only when asked (new option PREGROW, chain setting pregrow; off by default): by default the clip grows after a run whose flood reaches the terrain edge, as before 0.15.0. The window's DEM cell size and Grid size boxes are labelled (ft) (they hold feet since 0.18.0 but said (m)). See README.md.
    0.19.0: With ND Dam Hazard 2.21.0 and ND Dam Breach Runner 3.11.1. DWR unknown structures and dugouts: tool 1 reads DWR's Unknown Structures and Dugouts exports as well as the dams (kind detected or chosen; IDs UNK-<number> and DUG-<number>, because each export numbers its structures separately; status 'auto' keeps Intact dams, Intact / Unknown / blank unknown structures, Intact / Pending dugouts; a field missing under its dBase name is found under its GeoPackage name, so DWR_Dams.gpkg no longer fails). Tool 16 joins DWR's dugout records to DWR's dugout polygons (name, status, DWR class, DWR above-grade storage beside the LiDAR's; waste lagoons noted). Tool 3: storage leak guard (the fill stops where the pool spills out of the reservoir; for a dam of known height the curve goes on to the crest with the reservoir area at the spill level, otherwise it is held at the spill level; a pond whose pool already leaks at its own level gets a prism above the pool), DWR's maximum storage is the volume at the top of dam (the curve is stretched to it when the DEM falls short or runs past 1.5x; Absaraka 1,615 ac-ft against DWR 1,616, was 28,701; a DEM and DWR more than 3x apart is a CHECK with low confidence), a crest above pool + dam height is capped, the waterbody search distance can be set in the chain settings (wb_search_ft), a structure with no mapped water body uses the hydro-flattened water in the DEM, else the nearest dry basin, a missing height is estimated from the DEM (crest minus the lowest ground near the point), and triage-cleared dams also say when their inputs were estimated. Tool 16: a LiDAR release above DWR's total dugout storage is held to the DWR total and flagged. Estimated heights and storages are marked (h_src / stor_src), lower the class confidence, are named in the reports and summary.csv, and are recorded as estimated in dam.json.
    0.18.1: Tool 20 downloads ND DWR QL2 LiDAR over HTTPS from lidar.dwr.nd.gov for a dam (point and buffer, or the dam in dam.json), a county or the state, using the statewide tile index read in place; no FTP link or map-site visit needed, and it works where FTP is blocked (cloud machines, some networks). A pasted FTP link still uses FTP. 0.18.0: With ND Dam Hazard 2.19.0 and ND Dam Breach Runner 3.11.0. US units: depths, heights, distances, cell sizes, flows, volumes and areas are shown in feet, ft/s, cfs, acres and acre-feet in the HTML reports (hydrograph in cfs, depth map legend in feet), summary.csv (height_ft, qp_cfs), the Processing inputs (cell sizes, corridor and move distances in ft; saved models with the old metre parameters still run) and the window (DEM cell size and Grid size in ft; settings saved in metres are converted). Every result table keeps its metric working fields (the steps read each other by name) and gains a US twin of each (height_ft, td_qp_cfs, td_vw_acft, inv_area_ac, vel_fps, dv_ft2s ...). Step 7 also writes feet / ft per second companion rasters; the hydrograph and stage-storage CSVs have feet, cfs and acre-feet columns after the metric ones. Fixes from the Elm River run: breach direction uses the reservoir polygon touching the dam line, samples along the whole line, and the terrain wins when it disagrees with the water bodies (the breach was aimed into the reservoir); tool 8 finds AADT and the other fields whatever their case; the chain stops and says so when step 7 failed for every dam; an empty structures layer is a warning, not a refusal; the dams-without-a-line count honours the dams picked; the 3DEP failure names the blocked host. See README.md.
    0.17.0: With ND Dam Hazard 2.18.0 and ND Dam Breach Runner 3.10.0 (new: a HEC-RAS 2D dam-breach model from a Runner run). DEM elevation units: local tiles tagged in feet or US survey feet are converted to metres, untagged tiles are assumed metres with a warning, and DEMs this plugin writes are tagged 'm' (a 3DEP DEM warped to State Plane feet was read as feet by the Runner). Local tiles in more than one coordinate system are warped onto one EPSG:5070 grid instead of silently dropped. Move breach point takes the map centre in the map's coordinate system and refuses a move over 5 km. Zoom to selected is 400 m whatever the map's coordinate system. QL2 tile selection follows the curved southern edge in State Plane (the state box missed a 6 km strip). The terrain mosaic and dam_<ID>.tif are rebuilt when the tiles, cell size or extent change. The LISFLOOD-FP executable accepts a file name without an extension (Linux, macOS), and the self-test has an EXE parameter for the LISFLOOD-FP engines.
    0.16.0: Suite data and servers in Plugins > ND Dam Suite (one data folder for the three plugins) and Get data for this dam. Empty data layers fill from the dam folder, the offline pack or your DWR files (your choice always wins; the log says which). 3DEP terrain is read through the shared tile cache, so a tile is downloaded once. Download a DEM names the file after the dam or county, starts at 10 m, remembers its values and can write into the dam folder. The Runner hand-off records the DEM and layers it sent in dam.json. Not run in a real QGIS.
